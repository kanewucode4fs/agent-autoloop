# 需求文档

## 产品定位

让你的命令行 Agent 在后台自己接活、自己跟进到底；平时不烦你，遇到拿不准的事才发卡片找你拍板。

目标用户是已有命令行 Agent、需要把定时任务和外部事件交给它持续处理的人。中台负责记住事情、分派和等待；实际业务由规则指定的 Agent、脚本和插件完成。

当前阶段：`iteration`。以下“已实现”表示仓库已有对应实现和行为测试；本次实际执行了哪些验证，单独见[审阅记录](../06-交付审计/2026-11-23-文档审阅.md)。

## 已实现的功能需求

### REQ-1 接收事件并去重

用户可以从业务系统、Webhook 或脚本提交事件。一个来源重复发送相同编号，只记一次、只按规则接一次。

验收行为：缺少必填字段的事件被拒收；同来源同编号重复提交得到重复确认；不同来源的同编号互不冒充。

实现与规格：[事件判断](../../kernel/decide.ts)、[事件测试](../../tests/events.test.ts)、[HTTP 鉴权测试](../../tests/http.test.ts)。

### REQ-2 用可信规则决定执行范围

本人配置事件匹配方式、接单 Agent、工作目录、任务说明和权限；外部事件只提供资料。

验收行为：规则引用不存在的 Agent 或来源时报明确错误；事件正文不进入执行提示词，不能改变目录、权限或插件；坏规则不替换正在生效的规则。

实现与规格：[规则校验](../../protocol/rules.ts)、[执行约定](../../worker/contract.ts)、[规则测试](../../tests/rules.test.ts)、[提示词边界测试](../../tests/contract.test.ts)。

### REQ-3 自动安排定时任务

用户可以按规则时区配置 cron。电脑睡眠后恢复时，不把所有错过时刻同时补跑。

验收行为：计划到时才派发、同一时刻只触发一次；错过多个时刻只补最近一次；时区和夏令时按协议处理。

实现与规格：[定时计算](../../kernel/cron.ts)、[到期判断](../../kernel/due.ts)、[定时测试](../../tests/schedule.test.ts)、[时区测试](../../tests/cron.test.ts)。

### REQ-4 合并同一事项并限制并发

同一条规则下的同一对象持续作为一件事处理。规则可以按对象分开排队，并限制组、单条规则、Agent 和接单电脑的同时执行数量。

验收行为：没有 `parallel` 时整条规则为一个事项；有 `parallel` 时按对象区分；相同事项不同时领取两轮，各层并发上限共同生效。

实现与规格：[派发判断](../../kernel/decide.ts)、[领取测试](../../tests/runs.test.ts)、[队列开销测试](../../tests/queue-costs.test.ts)。

### REQ-5 让已有命令行 Agent 接活

接单程序在规则指定目录启动命令，将资料文件交给 Agent，读取最终消息和回执；CLI 登录和业务工具由 Agent 的环境提供。

验收行为：命令参数按原意传递；权限由对应适配器映射；非零退出或没有最终结果被报告；不把思考、工具过程或未结束的后台工作当成完成。

实现与规格：[接单程序](../../worker/worker.ts)、[适配器测试](../../tests/adapters.test.ts)、[ACP 测试](../../tests/acp.test.ts)。

### REQ-6 仅在需要时打扰本人

默认完成一轮不主动通知；需要本人决定时提交带选项的卡片。本人可以从通道、命令行或卡片链接回答。

验收行为：同一事项同一 key 的未结束问题不重复提问；通道回答须匹配回答者及原消息；重复回答不重复执行。

实现与规格：[卡片判断](../../kernel/decide.ts)、[卡片测试](../../tests/cards.test.ts)、[通道测试](../../tests/channels.test.ts)。

### REQ-7 回答后继续原事项

提问时结束一轮，等人期间不保留等待回答的 Agent 进程。本人回答后，中台发起新一轮，带上回答和原事项资料。

验收行为：回答叫醒提问的事项；条件允许时接回原 Agent 会话；换 Agent 不错误续接旧会话；只有实际处理回答后才把卡片记为执行完成。

实现与规格：[续接测试](../../tests/resume-thread.test.ts)、[端到端闭环](../../tests/loop.test.ts)、[停止与事项测试](../../tests/stops-and-threads.test.ts)。

### REQ-8 用回执跟进后续工作

Agent 可以在最终回执中发通知、提问、结案、安排复查或产生被规则许可的新事件。

验收行为：成功回执在一个事务内生效；重放同 token 同内容得到同一确认；错误回执只重写消息，不重做业务；没有会话可重写时保留原业务结果并通知本人。

实现与规格：[回执解析](../../worker/contract.ts)、[worker 测试](../../tests/worker.test.ts)、[事务与重放测试](../../tests/kernel.test.ts)。

### REQ-9 保留失败任务并有节奏地重派

临时失败的工作保留，期间新来的同事项事件并入重试轮。需要本人恢复登录、连接或验证的阻塞应提问并结束本轮。

验收行为：普通失败从 5 分钟开始退避、最长间隔 1 小时，第 3 次通知、第 10 次停止；额度限制在恢复前不继续给同 Agent 派活；本人停止的一轮不再重派。

实现与规格：[领取与重试](../../tests/runs.test.ts)、[额度限制](../../tests/usage-limit.test.ts)、[停止约束](../../tests/stops-and-threads.test.ts)。

### REQ-10 接单程序重启不丢在跑的工作和结果

接单程序通过本地执行记录恢复对进程的跟踪。停止任务时要停止其子进程。

验收行为：重启后继续观察原进程、提交已完成结果；进程查询失败不能认定退出；停止确认在整个进程树结束后发生；已续接会话的中断不换新会话重做。

实现与规格：[worker 测试](../../tests/worker.test.ts)、[进程查询](../../tests/worker-lookup.test.ts)、[Windows 进程](../../tests/windows.test.ts)。

### REQ-11 查看状态、历史与用量

本人可以查看规则、运行轮次、卡片、在线情况、未来复查和用量，并按规则或游标翻历史。

验收行为：`status --json` 输出状态快照；`runs` 翻历史，`why` 展示关联事实；用量按完成时间汇总，未报数据明确缺失，不伪造为零。

实现与规格：[状态汇总](../../host/state.ts)、[状态输出测试](../../tests/status-json.test.ts)、[用量测试](../../tests/status-cost.test.ts)、[历史测试](../../tests/cli-runs.test.ts)。

### REQ-12 暂停、恢复、补跑和手动运行

本人能暂停规则、查看跳过的事件，并选择是否补跑；已经在跑的一轮由停止命令处理。

验收行为：暂停期间不接新事件、不派队列，但保留回答和复查；恢复不自动补发跳过事件；补跑同事件只接一次；暂停中不允许手动运行和补跑。

实现与规格：[暂停测试](../../tests/pause.test.ts)、[控制接口测试](../../tests/pause-http.test.ts)。

### REQ-13 对外提供统一接口和插件入口

外部客户端可以使用 HTTP、SSE、MCP；新 Agent、来源、通道走同一插件目录。

验收行为：各类密钥互不越权；一轮 token 只操作本轮；安装插件不执行安装脚本；安装目录插件优先；MCP 仅暴露已有权限允许的操作。

实现与规格：[协议一致性](../../tests/conformance.test.ts)、[插件发现](../../tests/plugins.test.ts)、[MCP](../../tests/mcp.test.ts)。

### REQ-14 原生跨平台安装与维护

支持 Windows、macOS、Linux；允许一台机器运行全部角色，也允许独立接单电脑。

验收行为：安装不覆盖已有配置；join 不覆盖已配置机器；后台服务使用对应系统机制；备份可在运行中进行，恢复必须停中台；卸载保留规则、密钥和记录。

实现与规格：[安装测试](../../tests/install.test.ts)、[加入测试](../../tests/join.test.ts)、[备份测试](../../tests/backup.test.ts)、[卸载测试](../../tests/uninstall.test.ts)。

### REQ-15 自动跟进 GitHub PR 交付

配置交付插件后，PR 标签触发审查、检查、合并、发布跟踪和健康版本核对；只审查和需本人决定时有独立出口。

验收行为：设置只读固定 main；不检出或运行 PR 代码；只接受当前提交的必需检查；合并前重读 head/main/base/标签；Ship 和健康版本共同确认上线。

实现与规格：[交付实现](../../plugins/delivery/delivery.ts)、[交付测试](../../tests/delivery.test.ts)、[审查隔离测试](../../tests/delivery-review.test.ts)。

### REQ-16 提供可改造的场景模板

提供晨报、Issue 跟进、告警、反馈、网站巡检、飞书摘要、邮箱分诊、浏览器交接等配置和任务手册。

验收行为：样例规则通过现有校验；样例脚本用假外部服务验证；启用前替换目录、身份和业务地址。样例不等于用户真实账号已验收。

实现与规格：[场景目录](../../examples/recipes/)、[规则样例测试](../../tests/recipes.test.ts)、[业务样例测试](../../tests/business-recipes.test.ts)。

### REQ-17 中控页面查看所有任务

状态：计划中，尚无页面代码或已批准的交互设计。

已确认目标：本人能够在一个页面看到所有任务。可使用现有[本人接口](../protocol.md#本人看全局回答结案停止)和事实流获取数据。

## 非功能需求

- **数据可靠性**：事实日志为业务权威；日志与投影同事务，失败整体回滚，重建不重新执行业务。
- **权限边界**：凭据按角色分开；规则是执行依据；卡片页面转义外来文字，打开链接不自动回答。
- **可追溯**：规则版本、事件、回执、回答可关联；快照可从日志序号续读。
- **兼容性**：既有 /v1、规则、插件、命令与数据保持兼容；破坏性变化按[版本约定](../protocol.md#版本与兼容)处理。
- **依赖与部署**：Node 24 自带模块满足运行需要，不增加运行时包。
- **性能**：记录实测，不设置发布达标线；空闲与千连接内存分开，写入逐笔落盘，不能改成批量提交获取好看数字。

## 使用约束

这是“至少一次”的执行系统。中台能去重事件和回执，不能保证外部支付、发消息等业务副作用只发生一次。任务 Skill 必须先核实外部状态再重复操作。

`askFirst` 是提示给 Agent 的约定，`access` 由适配器映射，不能替代系统账号和操作系统隔离。普通卡片链接持有者可回答该卡片，不能当成已验证身份的登录入口。

本项目当前没有 Agent 记忆、模型路由、多租户、插件市场或可视化工作流画布。中控页面目标不等于同时承诺这些能力。

# 技术架构

## 技术骨架

Agent Autoloop 是 Node 进程承载的事件中台。内核确定性判断产生事实，外壳提供时间、存储连接和 HTTP；Agent、来源、通道以插件接入。默认一台电脑、一个 up 进程即可运行中台、worker 和本机通道，也能拆到不同电脑。

[架构图](../architecture.svg)展示连接方向，[协议](../protocol.md)定义跨进程接口，[状态与转换](../state-machines.md)列出每个对象的权威状态。本文解释实现结构和取舍，不复制完整字段协议。

## 技术栈和运行条件

| 层 | 当前实现 | 说明 |
| --- | --- | --- |
| 运行时 | Node.js >= 24，ES module | 原生执行可擦除类型的 .ts；没有打包和转译运行步骤 |
| 语言 | TypeScript | 类型检查使用 TypeScript 7.0.2 |
| HTTP | Node HTTP + Web Request/Response | 没有 Express、Fastify 或 Web 框架 |
| 持久化 | node:sqlite，SQLite WAL + FULL | facts 与投影每次一起提交，成功落盘后应答 |
| 校验 | 手写边界校验 + JSON Schema 2020-12 | 发布 Schema 与实际校验用行为测试对照 |
| 测试 | node:test、node:assert | 真实临时 HTTP、进程与 SQLite；外部平台用本地替身 |
| 静态工具 | @types/node 26.6.4、Prettier 3.9.10 | 三个包都是开发依赖；无 dependencies |
| 常驻 | launchd / systemd 用户服务 / Windows 登录任务 | 不提供 Docker 镜像或 Compose 编排 |
| 当前界面 | CLI、通道卡片、无脚本卡片表单 | 中控页面后续开发，当前没有前端工程 |

版本按 package.json 与锁文件记录；软件自身版本只写 Git tag，不写入版本文件。Node 自带模块并不代表外部 Agent、gh、飞书 CLI 等业务工具已经安装。

## 模块依赖

```text
bin → cli → host → kernel / protocol
           │       │
           │       ├── HTTP、时钟、SQLite、配置、系统服务
           │       ├── worker → plugins/<name>/agent.ts
           │       └── channels → plugins/<name>/channel.ts
           └── MCP → protocol/client → 同一组 HTTP 接口

请求 → kernel/http → decide(view, input, now, environment)
                              ↓ facts
                 store.commit → evolve → 持久投影
                              ↓
                   应答 / 状态快照 / 事实流
```

内核不主动发送外部请求、不读取时钟或随机数、不认识产品。SQLite 投影是内核的存储实现，连接由 host 创建并传入；不能把“确定性内核”理解成完全不使用数据库。

## 核心文件及调用边界

| 文件 | 责任 | 不能越过的边界 |
| --- | --- | --- |
| kernel/decide.ts | 按输入、视图、时间及环境判断，生成本次事实 | 不直接写持久投影，不启动 Agent |
| kernel/evolve.ts | View、临时变更覆盖层、事实演进、持久投影 | 只有 evolve 持久化业务投影变化 |
| kernel/store.ts | 锁定最新视图、提交事实、重建 | 只有 commit 追加业务日志 |
| kernel/query.ts | 卡片、轮次和资料的内核读模型 | 不替代事实写入 |
| kernel/due.ts | cron、复查、退避、心跳、离线等到期索引 | 到期索引与事实同事务保存 |
| kernel/credentials.ts | 密钥身份、轮次和卡片能力凭据 | 普通密钥只存哈希；能力 token 不进日志 |
| kernel/http.ts | 鉴权、路由和 Web Request/Response 处理 | 访问边界与协议一致 |
| kernel/card-page.ts | 转义文字、生成无脚本表单 | GET 不回答，不解释外来 HTML |
| host/runtime.ts | SQLite、主密钥、规则载入、执行和快照 | 时间和文件从这里进入内核 |
| host/http.ts、host/server.ts | Node/Web 请求转换和监听 | 请求转换层不承载业务判断 |
| host/state.ts | 查询视图、状态和完成时间用量汇总 | 只读；查询列随启动重建 |
| host/up.ts | 组合中台、worker、通道和退出清理 | 一份配置决定本机启用哪些角色 |
| host/plugins.ts | 插件定位与导入 | 安装目录优先，不能由事件指定路径 |
| worker/contract.ts | 提示词、资料文件引用、最终回执解析 | 外来正文不进入指令部分 |
| worker/worker.ts | 领取、持久化 entry、启动、恢复、停止和提交 | 未确认进程结束不能报完成 |
| worker/usage.ts | 会话累计用量换算为本次增量 | 缺可信基线时不伪造用量 |
| cli/main.ts | 帮助、参数验证和命令协调 | check/dry-run 不能偷偷写中台 |
| cli/mcp.ts | 换行分帧 JSON-RPC 和已授权工具 | 不开放任意 HTTP 地址执行 |

## 持久化和读模型

### 一次输入怎样提交

1. host 给出当前时间、主密钥材料及请求，调用 commitLatest。
2. store 开启 BEGIN IMMEDIATE，读取最新投影，防止 CLI 和服务同时写时使用旧快照。
3. decide 在只读基础视图上保留这次的变更，产生带序号、时间和类型的 facts。
4. commit 追加事实，evolve 更新投影、索引、游标和编号高水位。
5. 同一事务成功后应答；任一写入失败整体回滚。

没有变化的输入不写事实，例如短于心跳记录间隔的重复报到。事实重放只应用已记录的变更，不重新匹配规则或执行业务。

### 物理存储

| 存储对象 | 内容 |
| --- | --- |
| facts | 单调 seq 和 JSON 事实；唯一业务权威 |
| projections | collection + key 对应的 JSON 投影记录 |
| projection_meta | 当前日志游标、编号高水位和格式指纹 |
| projection_refs | 投影记录关联的事实序号索引 |
| projection_pending | 按卡片和通道查找待投递记录的派生索引 |
| 部分 / 表达式索引 | 事件去重、轮次队列、卡片、复查和到期等按需查询 |

这里是现有 SQLite 存储的说明，不提供另一套建表脚本或迁移文件。完整列和索引定义在 kernel/evolve.ts，查询视图在 host/state.ts。

### 逻辑投影

| collection | 含义 |
| --- | --- |
| events / run_events | 事件及其与轮次的关联 |
| runs | 排队、领取、执行尝试、会话、结果和用量 |
| cards / deliveries | 问题及通知、各通道的投递版本和重试 |
| timers / schedules / due | 业务复查、cron 计划和统一到期索引 |
| seen | worker 和通道最近被记录的报到 |
| keys | 按角色和名字保存的密钥哈希 |
| config | 生效规则及其版本 |
| pauses / limits | 规则暂停和 Agent 额度限制 |

正常启动复用投影。kernel/evolve.ts、kernel/credentials.ts 及主密钥参与格式指纹；指纹变化或旧版缺少元信息时，在同一事务逐条重建。主密钥自身丢失不能靠日志恢复。查询 SQL 视图每次启动重建，改查询列不要求重放业务日志。

## worker 生命周期

每次领取的本地目录为数据根下 `worker/runs/<run>-<attempt>/`，记录 entry.json、context.json、各 turn 的输出和退出状态。

worker 先持久化执行信息，再启动独立监督机制。Unix 使用进程组与登录 shell，Windows 使用 Node 监督进程和 PowerShell Job Object。接单程序重启后读取原记录并核对真实进程。

默认执行超时为 180 分钟，可用 Agent 的 timeout 调整；已读到最终结果但不退出的程序留 30 秒退出时间；停止先请求结束，10 秒后仍未退出则强制停止整个进程树。已完成输出保留 14 天，没有未提交 entry 的过期目录才会被清理。

结果先写本地，再向中台提交；网络失败继续保留。回执错误只请求重写，最多两次。恢复原会话后已经开始的轮次若中断，必须留在原会话按中台节奏重派。

## 接口与客户端

| 使用方 | 主要入口 | 身份 |
| --- | --- | --- |
| 来源 | `/v1/events`、`/v1/events/<id>`、`/v1/tell` | source |
| 接单程序 | /v1/work；指定任务的 /v1/tell | worker |
| 本轮执行 | `/v1/runs/<id>/started`、`/result` | 本轮 token |
| 通道 | /v1/cards/next、delivered、failed、answer | channel |
| 本人 | /v1/state、runs、why、stream、卡片及规则控制 | owner |
| 健康检查 | /healthz | 无密钥，只返回健康与运行提交 |
| 卡片表单 | 能力链接对应的表单 | 仅该卡片链接的权限 |

具体方法、请求体、响应、状态码和字段约束以[协议](../protocol.md)及[发布 Schema](../../protocol/schema.json)为准。

本人客户端先读 /v1/state 的 seq，再从 `/v1/stream?after=<seq>` 接续，可用 Last-Event-ID 重连。状态默认返回最近 60 轮，历史通过 before 翻页；规则历史接口排除仍 queued/claimed 的轮次。SSE 不向客户端暴露密钥哈希或能力凭据。

MCP 是 stdio 客户端层，固定支持 2025-11-25 版握手，工具按本机持有的 owner/source 密钥展示。不要放进 worker 启动的 Agent 的用户级配置，否则它会获得本人的能力。

## 插件机制

插件路径统一为 `plugins/<name>/{agent,channel,source}.ts`。host/plugins.ts 先找数据根 plugins，再找随引擎提供的插件。插件必须是本人安装的可信代码；add 仅克隆，不运行安装脚本。

| 类别 | 内置实现 |
| --- | --- |
| Agent | claude、codex、command、acp、dsh、zcode、delivery |
| 来源适配 | github、gitlab |
| 通道 | desktop、feishu、webhook |
| Webhook 消息模板 | 钉钉、企微、Slack、Discord |

Agent 适配器负责命令、最终输出和会话读取；通道负责发卡和平台身份；来源适配器负责验签和翻译。新增产品不能把产品名、对外请求或专用逻辑塞回 kernel、host、protocol、worker。

浏览器属于执行环境，不由中台附带。后台 codex exec 不能假定继承桌面应用浏览器连接；ACP 权限也依赖对端协议实现，不能当成系统沙箱。

## 交付插件的隔离

交付插件作为普通 Agent 运行，队列、并发和重派仍由中台负责。它从 main 的固定提交读 ops/delivery.json 与审查点，用裸 Git 对象生成只读文字快照，不能执行 PR 中的程序、配置、测试或 hooks。

审查、检查、合并、Ship 和健康版本是不同阶段。审查账本与可信提交状态绑定提交和审查器；同一提交不能靠重审抹掉已有挡上线问题。详细逻辑见[状态与转换](../state-machines.md#pr-交付审查发布)。

## 设计取舍

| 选择 | 解决的问题 | 代价和限制 |
| --- | --- | --- |
| 被动内核、外接插件 | 业务凭据和产品变化留在外部 | 外部连接和登录需分别配置 |
| 确定性事实 + 事务投影 | 可重放、可追踪、提交不半成 | 日志不压缩，磁盘随历史增长 |
| 逐笔 WAL + FULL | 应答代表本次已提交 | 写入吞吐受落盘延迟影响 |
| 按需 SQLite 索引 | 不把全部历史常驻 JS 内存 | 全局汇总与首次重建仍随历史增大 |
| 一轮不等人 | 等决定不占 Agent 进程 | 回答需新一轮，长会话续接仍有费用 |
| 至少一次执行业务 | 失败可恢复、不丢工作 | 外部动作必须自行核对和幂等 |
| 零运行时包 | 安装链短、边界可审阅 | 不提供现成前端、浏览器驱动或平台 SDK |

## 验证和性能口径

行为测试覆盖身份、去重、事务、卡片、领取、进程、安装、插件和交付。tests/purity.test.ts 守内核与产品边界；tests/simulation.test.ts 和 sim/ 使用同一内核检查重放及不变量，不维护另一套“更快的内核”。

npm test 含固定种子 20 万步和有界穷举；PR 按范围分流，每日检查补强杀、变异和最新 Node。实际运行要求见[部署指南](../04-部署文档/部署指南.md#开发验证)。

性能只引用[现有实测](../protocol.md#历史增长实测)，不把本次文档整理当成新基准。状态汇总和全量重建的历史增长代价已有实测，不能据此宣称无容量限制。

## 后续页面的接入点

中控页面目标是查看所有任务，可以从本人状态、历史和事实流开始。当前没有前端依赖、页面服务、前端状态库或登录体系；这些不能写成既成架构。开工时同步更改“没有界面”的项目约束，确定凭据传递和页面部署边界。
